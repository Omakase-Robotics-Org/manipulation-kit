# Licensing status — READ BEFORE MAKING THIS REPOSITORY PUBLIC

**There is no `LICENSE` file in this repository, and that is deliberate.**
manipulation-kit is intended to become OSS for "second development" customers
who receive a D1 with `d1-firmwared` pre-flashed. It is **private today**
because two questions are still open, and both of them have to be answered by a
person, not by a default:

1. **What licence do we grant on our own code?** (Apache-2.0, BSD-3, something
   with a patent grant, something source-available?)
2. **Which of the vendor CAD assets in this repository may we redistribute at
   all**, and under what terms?

Shipping a `LICENSE` before those are settled would be worse than shipping none:
an Apache-2.0 header over a directory of unlicensed vendor STLs is a claim we
cannot back.

### The mesh-free model is the clean one

`src/manipulation_kit/description/d1/d1.urdf` — and therefore the whole
`d1-collision` variant and everything in `manipulation_kit.guard` — contains **no
vendor geometry at all**. It is boxes, cylinders and spheres derived from
measurements, generated by our own generator. If the vendor-mesh questions take
a while, a first public release consisting of the code plus `d1.urdf` and *no*
STL/OBJ is available without waiting for anybody.

That is not a hypothetical: `mkit-urdf export d1-collision` already produces
exactly that, in one file, and `dist/d1-collision/` is it, committed.

## What is NOT in this repository, and why it does not help

The ~96 MB `d1/meshes/body_hifi/` decorative visuals were deliberately left
behind (see the README). That was a size decision first, but it is also one
fewer directory of unlicensed vendor CAD to clear.

The vendor `.so` files (`the arm vendor's SDK shared library`, `libKine.so`), the vendor `sdk/`
source tree and the C++ examples are **not here** — they stayed in d1-sdk and
are being retired into `d1-firmwared`. `DISTRIBUTION.md §7.2` requires the
vendor source stay internal, and this repo honours that.

## Decisions needed (Shu / legal)

- [ ] **Our licence.** What do we grant on Omakase-authored code in this repo?
- [ ] **the arm vendor arm meshes.** Redistribution right — yes/no, and on what terms.
      Blocker for shipping `d1-arm`, `d1-yubi` and
      `d1-wholebody-gripper` to anyone outside the org.
- [ ] **D1 body + gripper CAD.** Same, for our own robot's vendor-produced CAD.
- [ ] **Fallback plan.** If the mesh answers are slow: publish code + `d1.urdf`
      only, and keep the mesh-bearing variants behind the private repo.
- [ ] **Attribution file.** When a `LICENSE` lands, add a `NOTICE` carrying the
      Apache-2.0 attributions for `yubi_description` and the DH116S descriptions.

Until every box above is ticked, this repository stays **private**.
